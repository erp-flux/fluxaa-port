# 11. Exigences non fonctionnelles et architecture

> Chapitre **rédigé** (FLX-SPEC-003, onglet principal, sections 5 et 10), tenu à la main à chaque livraison ; sa source de vérité est le code livré : quand un chapitre et le code divergent, le code fait foi et l'écart est consigné dans `docs/ARCHITECTURE.md` §11.

## 11.1 Architecture technique

*Schéma : architecture · 3 surfaces, 1 couche de services, 2 bases — dessiné dans FLX-SPEC-003 (onglet principal).*

La plateforme est une application serveur unique (monolithe modulaire) : les trois surfaces appellent une seule couche de services, qui écrit dans deux bases PostgreSQL. Ce choix est une règle de construction, pas un détail : une réécriture qui répartirait les règles entre un front et plusieurs micro-services perdrait la garantie « une règle, un endroit » sur laquelle reposent les points d'arrêt et le journal.

**Pile livrée.**

| Composant | Choix | Rôle |
| --- | --- | --- |
| Langage, cadre | Python 3.12+, Django 5.2 | modèles, migrations, administration, i18n, sessions |
| API | Django REST Framework 3.15, drf-spectacular 0.28 | points d'accès, schéma OpenAPI 3 (`/api/schema/`, `/api/docs/`) |
| Base de données | PostgreSQL 16 × 2 (`default`, `secure`), psycopg 3 | registre ; domaine N4 isolé ; déclencheurs d'intégrité ; rôles d'exécution sans `DELETE` |
| Interface | gabarits Django + HTMX, CSS maison (`static/css/fluxaa.css`), JS minimal (`app.js`, `field.js`, `sw.js`) | pages serveur, fragments HTMX (tableau AIS), appli terrain PWA avec service worker |
| Sécurité | pyotp (TOTP), cryptography (Fernet, HMAC), politique CSP, limitation des tentatives | second facteur, chiffrement N4, scellement, durcissement |
| Serveur | gunicorn, whitenoise, Caddy (TLS automatique) | exécution, statiques, frontal HTTPS |
| Tâches de fond | commande `run_scheduler` (boucle 60 s) | contresignatures tacites, alertes, résumés quotidiens, expirations, webhooks, purge AIS |
| Optionnels | `anthropic` (assistance IA, EF-17), `pyais` + `websockets` (écoute AIS) | désactivés par défaut ; aucune donnée N4 ne leur parvient |
| Exploitation | Docker Compose (db, web, scheduler, caddy, profil `ais`), lanceur Windows de démonstration | déploiement, sauvegardes, restauration |

**Organisation du code.** Cinq applications Django : `core` (ports, organisations, utilisateurs, postes, rôles, MFA, limitation, middleware CSP, garde-fous de modèles et de base), `registry` (tout le registre : modèles, services, vues web, gabarits, commandes), `api` (vues DRF, authentification par jeton ou lien, représentations JSON), `secure` (domaine N4, base distincte), `ais` et `ai` (modules optionnels). Dans `registry`, `models.py` porte les entités et les énumérations, `catalog.py` les données de référence, `bootstrap.py` leur chargement idempotent, `services/` les règles (un module par domaine, voir le schéma), `views.py` les écrans, `templates/registry/` les gabarits, `management/commands/` les commandes d'exploitation.

**Conventions de développement (O).**

1. Une vue (web ou API) résout l'acteur (`services/context.actor_for_call` ou `port_actor`), appelle une fonction de service, traduit l'exception métier (`RegistryError` et ses sous-classes `PermissionRefused`, `RuleViolation`, `HoldPointRefused`, `LockRefused`, `NotVisible`, `StrongAuthRequired`) en message ou en code HTTP, et redirige ; elle ne contient aucune règle.
2. Une fonction de service est atomique (`transaction.atomic`), vérifie les droits avant d'écrire, écrit l'objet puis son entrée de journal (`services/journal.record`) avec un résumé français et anglais et une charge utile JSON, puis notifie (`services/notifications.notify`).
3. Les listes visibles passent par `rights.visible_*` ; un objet non visible est un 404, jamais un 403.
4. Toute décision ou acte sensible exige `actor.strong_auth` (second facteur de moins de `FLUXAA_MFA_STEPUP_SECONDS`, 8 h) : la vue redirige vers la vérification, l'API répond `403 strong_auth_required`.
5. Les heures sont stockées en UTC (`DateTimeField` avec fuseau), affichées dans le fuseau du port (`Port.timezone`) ; les formulaires saisissent l'heure du port (`parse_local`).
6. Toute chaîne visible est traduite (`gettext`) ; les libellés de référence portent deux colonnes `_fr` et `_en` ; le français est la langue source des fichiers de traduction (`locale/fr/`).
7. Aucun `DELETE` dans le code applicatif ; une migration qui ajoute une table du registre ajoute aussi son déclencheur d'ajout seul ou de non-suppression.
8. Chaque règle nouvelle arrive avec son test (`tests/`, pytest, PostgreSQL requis) et sa ligne de traçabilité (`docs/TRACABILITE_CDC.md`).
9. Les identifiants techniques (codes de tâches `M0:02`, de jalons, de demandes, de documents, références d'escale) ne changent jamais : l'export, l'API et les intégrations les portent.

## 11.2 Exigences non fonctionnelles

| Id | Exigence | Priorité | Mise en œuvre livrée / vérification |
| --- | --- | --- | --- |
| NF-01 | **Journal chaîné** : chaque acte (`JournalEntry`) porte `seq` par port, `prev_hash`, `hash` SHA-256 (contenu + empreinte précédente), auteur (rôle, organisation, personne ou lien), résumé FR/EN, charge JSON, rôles qui peuvent le lire ; chaque consultation, téléchargement, export, accès administratif est un `AuditEntry` chaîné de la même façon ; `verify_journal` recalcule les deux chaînes ; l'export d'escale est vérifiable hors plateforme (`scripts/verifier_export.py`) | O | `services/journal.py`, `test_journal_chain_detects_tampering` |
| NF-02 | **Scellement** : signatures de documents, contresignatures, autorisations portent un sceau HMAC (`FLUXAA_SIGNING_KEY`) ; interface prête pour une autorité d'horodatage RFC 3161 (`FLUXAA_TIMESTAMP_PROVIDER = local` ou `tsa`, `FLUXAA_TSA_URL`) ; le niveau juridique de signature reste un point ouvert (O04) | O | `apps/core/crypto.py` |
| NF-03 | **Sécurité des pages** : `Content-Security-Policy` (scripts de la plateforme seulement, aucun script en ligne, `frame-ancestors 'none'`), HSTS, `nosniff`, `Referrer-Policy`, cookies `Secure`/`HttpOnly`, CSRF sur tout POST ; un fichier déposé est servi en octets ou sous `sandbox` ; HTML déposé jamais rendu comme page du site | O | `apps/core/middleware.py`, `tests/test_security.py` (46 attaques rejouées) |
| NF-04 | **Authentification** : mot de passe + TOTP (rôles décideurs et administrateurs), ré-authentification pour décider (8 h), limitation des tentatives (`AttemptWindow`), une seule page de connexion, jetons d'API créés après second facteur, liens sans compte hachés (jeton 256 bits, code 8 caractères) | O | `apps/core/mfa.py`, `throttle.py`, `apps/api/authentication.py` |
| NF-05 | **Domaine N4** : base PostgreSQL distincte (`secure`), rôle d'exécution distinct, pièces chiffrées Fernet avec des clés propres (`FLUXAA_N4_KEYS`, rotation supportée), dépôt en écriture seule avec récépissé, lecture par SUR et CAP journalisée et signalée par courriel à l'autorité de sûreté ; aucun objet N4 dans l'export, l'API du registre, l'assistant | O | `apps/secure`, `test_s5_n4_partitioning` |
| NF-06 | **Intégrité de la base** : déclencheurs `fluxaa_refuse()` (UPDATE/DELETE/TRUNCATE selon la table), référence d'escale immuable (`fluxaa_reference_immutable`), document figé (`fluxaa_document_frozen`), rôles `fluxaa_app` / `fluxaa_secure_app` sans `DELETE` ; les migrations s'exécutent sous le rôle propriétaire (`FLUXAA_MIGRATE=1`) | O | `*_database_guards`, `apply_db_grants`, `test_database_refuses_update_and_delete` |
| NF-07 | **Hors ligne (appli terrain)** : page `/escales/<id>/terrain/` installable (manifest, service worker `sw.js`), paquet de travail chargé à l'ouverture (`GET C/field-bundle/` : tâches, jalons proposés, causes, contresignatures attendues), saisies placées dans une file IndexedDB (`fluxaa-field`, magasins `bundles` et `queue` par `client_uuid`), rejouées à la reconnexion par lots de 50 (`POST C/sync/`) dans l'ordre de l'heure de l'appareil, idempotentes par `client_uuid` ; conflits conservés et signalés ; grandes cibles tactiles (gants), photo jointe, mode avion testé en recette | O | `static/js/field.js`, `services/sync.py`, `test_s6_offline_conflict_creates_dispute` |
| NF-08 | **Langues et formats** : interface FR et EN (bouton FR/EN, `User.language`, `Port.default_language`), tous les libellés de référence en deux colonnes, documents générés bilingues ; heures UTC stockées, fuseau du port affiché ; nombres au format de la langue ; dates ISO 8601 dans l'API et l'export | O | `locale/`, `apps/core/numbers.py` |
